# R2HA: Antigravity Harness Upgrade Plan

**Goal**: Implement a new harness to parse conversational history from Google's Antigravity agents across `.pb` files in `~/.gemini/antigravity/conversations/`.
**Current status**: Mothballed & commented out antigravity.ts harness because Google encrypted the .pb.

## Background
Antigravity chat histories are stored natively as Protocol Buffers binary files (`.pb`), but our analysis confirms they are **entirely encrypted** using `AES-256-GCM` with file-unique 12-byte IVs and maximum entropy (8.00 bits/byte). They are not standard Protobuf files in their raw state on disk. To parse them, we must first decrypt them.

## Encryption Investigation Summary

### 1. The Master Key (Chromium Safe Storage)
On Windows, Antigravity protects its master encryption key using the Windows DPAPI within the `%APPDATA%\Antigravity\Local State` file. We successfully extracted and unprotected this key using a PowerShell script. 
The 256-bit AES master key in Base64 is:
```text
wv7MLloB8wHUNpSrTjql+N38J3gTo+8c/pUtUUg0DN4=
```

### 2. PBKDF2 Testing Matrix
Using the extracted 32-byte DPAPI key directly as the AES-256-GCM key inside generic decryption routines against the `.pb` files failed with an AuthTag validation error.
We iteratively tested standard key derivations via `tmp_decrypt_test2.ts`:
- Chromium default: `saltysalt` salt, 1003 iterations, SHA-1 / SHA-256
- Zero-salt and empty-salt derivations
- Alternate AuthTag length truncations

**Result:** All permutations failed.

### 3. The True `mcpEncryptionKey` JWK
By reverse-engineering the minified Antigravity Electron bundle (`workbench.desktop.main.js`), we discovered that the encryption relies on an `mcpEncryptionKey`.
- Antigravity queries the `ISecretStorageService` (VS Code's native Secret Storage) for `mcpEncryptionKey`.
- If found, it parses it as a JSON Web Key (JWK) and imports it into `crypto.subtle` for AES-GCM operations.
- The DPAPI Chromium Safe Storage key is ONLY used by Electron's `safeStorage` wrapper to encrypt the JWK itself when saving it to disk/keychain.

### 4. Storage Location Search
We exhaustively searched the filesystem to find where the `ISecretStorageService` persists the `mcpEncryptionKey` JWK:
1. Checked `globalStorage/state.vscdb` (SQLite `ItemTable` for `%mcpEncryptionKey%` / `%secretStorage%`). Result: Empty.
2. Checked Windows Credential Manager via `keytar` across target services: `Antigravity`, `Antigravity Safe Storage`, `vscode`, etc. Result: Empty.
3. Searched the roaming `%APPDATA%\Antigravity\User` directories recursively for the string. Result: Empty.

## Conclusion & Next Steps
We have parked the investigation. The `.pb` files are encrypted using a standalone AES-GCM JWK that is generated by the application and stored in an obfuscated OS-level keychain or obscure state table.
To proceed in the future:
1. Find the exact path/database where Antigravity's `ISecretStorageService` persists its encrypted secrets.
2. Extract the wrapped JWK.
3. Un-wrap it using the DPAPI `Local State` key via Electron's exact C++ `safeStorage` decipher logic.
4. Pass the clear JWK to standard AES-256-GCM decipher block to extract the `.pb` texts.
